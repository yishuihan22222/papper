# V3失效机制专项诊断

日期：2026-10-16。当前结论：**实现一致性检查通过，但风险聚合公式存在已定位、需要修正或提供业务依据的机制风险，V3暂不能作为机理已经验证的投稿定稿。** 本次只诊断，未改变生产公式或优化算法。

## 1. 本次复核了什么

- 阈值扫描中7个“初始损伤扩大而最终失效减少”的组合，逐一对两个起点做14次无共享缓存的冷启动复现；最终失效节点集合均与原结果完全相同。
- 代表性SVD选点损伤、θ=0.42，对节点和边各做3套固定随机顺序重排，保持逐节点需求不变；两个起点下的终态集合均保持一致。
- 独立重建风险各分量，与生产函数对照；同步跟踪两条传播链，找到集合包含关系首次被破坏的轮次。
- 共48项诊断检查通过；生产核心文件哈希运行前后一致。这里的“通过”说明复现和分解一致，不代表公式的业务含义成立。

## 2. 已定位的实际例子

SVD选点损伤，θ=0.42。小起点为8个初始失效节点，大起点为包含这8个节点的119个初始失效节点。终态分别为198个（80.49%）和143个（58.13%）失效。

初始风险判定时尚未发生分数向下跨阈值；第一轮新增失效后，在第二次风险判定（代码round=1）首次出现下面的翻转：

| 项目 | 较小失效状态A | 较大失效状态B |
| --- | --- | --- |
| 同时存活的节点 | 新汉正西物流园E座 | 同一节点 |
| 利用率 | 1.0000 | 1.0000 |
| 总风险分数 | 0.426178 | 0.419448 |
| 按θ=0.42判定 | 失效 | 不失效 |

此时A的失效集合仍是B的子集。B−A的分数变化为：

| 风险分量 | 变化量 |
| --- | ---: |
| 失效邻居比例项 | +0.124051 |
| 失效边风险均值项 | −0.032740 |
| 跨区比例均值项 | −0.079433 |
| 成本均值项 | −0.018608 |
| 容量项、利用率项、场景加项 | 0 |
| 合计 | 约−0.006730 |

把B的利用率固定为A的利用率后，这个向下跨阈值仍存在。因此，就这一首次翻转而言，平均属性项的稀释足以造成风险下降；不能将其归因于节点分配负荷降低。后续终态差异还包含传播链连锁变化，不能用这个单节点分解直接量化全部终态差异的因果贡献。

## 3. 这是哪一类问题

当前公式对“已失效邻居”的风险、跨区、成本、能力属性取平均。失效集合增大时，加入一些较低属性值的邻居，就可能把这些均值拉低。失效邻居数量增加带来的正向压力，不一定抵消均值下降；于是发生风险稀释。

独立解析小例也能展示这一数学性质：固定总邻居数10、其他项和利用率不变，失效邻居从1个增加到2个、其风险均值从1降至0.5，按当前权重可使分数从0.318963降至0.240296。这只是公式性质演示，不是现实设施观测。

不能要求所有物理网络都必须满足“初始破坏更多，级联必然更大”。有研究表明，在某些过载模型中选择性移除组件可以抑制级联。[Motter, 2004，官方摘要](https://journals.aps.org/prl/abstract/10.1103/PhysRevLett.93.098701)

但该文讨论的负载网络防御机制，不自动验证本项目的平均分数规则。本例首次翻转的利用率未下降；本项目又使用严格额定能力分配，不应直接借用“过载缓解”解释。当前缺少支持这种风险稀释的物流业务依据，因此必须将其视作需要修正或论证的模型机制，而非默认作为有价值的新发现。

## 4. 阈值跳变与这个问题要分开

通道中断在θ=0.42–0.44的终态突变，是固定公式下真实复算得到的敏感性现象。突变本身既不能证明公式错误，也不能证明真实网络存在临界相变。

风险稀释是另一项更具体的机制问题，已有节点级证据。处理它之前，不应将当前阈值突变直接写成“真实物流网络级联临界性”，也不应优先用更复杂算法追求更好分数。

## 5. 下一版应优先处理什么

1. 保留V3和本轮结果作为固定对照，沿用已有备份，另建候选版本。
2. 区分节点自身易损性、邻居失效带来的压力、分配后利用率三类量。邻居压力优先研究非负影响累加、固定全邻域归一化等有明确含义的形式，避免随着失效邻居增多而自动稀释；不为获得有利结果调整权重。
3. 若保留减载/保护类非单调响应，必须明确它通过什么业务机制发生，并做能区分该机制和均值稀释的对照。局部压力项的单调性也不等于完整负荷耦合系统必然单调。
4. 先做节点级构造小例、起点嵌套对照和分量审计，再重做同一组阈值扫描；随后恢复算法比较。

已有数据来源、网络构造、严格分配、累计预算和可复算代码仍可使用。需要优先返工的是失效传播规则及相应机理论证，不必把所有资料和代码推倒重来。
