# 双机制解耦设计审查与建议：V5候选

日期：2026-10-16。本文件为设计审查，不是新版本实验完成报告。正式V3/V4、数据和结果均未改。保留“过载或风险传播”的结构；下面列出落地前需要明确的数学、调度和评价口径。

## 1. 总体判定

对当前存活节点v，分别计算：

`O_v = [L_attempt_v / K_nominal_v > gamma + epsilon_u]`

`R_v = risk_enabled AND [count_v > 0] AND [P_v >= theta_risk]`

`new_failure_v = O_v OR R_v`

这里的独立是分别定义、分别判定；两者共享受损集合、网络和重分配过程，不意味着统计独立或因果贡献可直接相加。风险模式结束时，不能让函数提前返回而关闭物理过载判断；应只关闭明确约定的风险通道。应在论文中解释risk_enabled与外部灾害结束、基础设施依赖仍存在之间的关系。

gamma表示失效负载阈值/额定能力；rho表示分配允许的尝试负载上限/额定能力，两者必须分开。epsilon_u仅为求解器数值容差，不能作为业务安全余量，具体值应与LP可行性残差共同记录。

## 2. 风险压力公式需要保留逐边非负累积

建议：

`a_vj = .21 + .16*p_vj + .12*cross_vj + .10*min(cost_vj/.45,1) + .09*(1-min(edgecap_vj/55,1))`

`P_v(F) = sum(a_vj for j in N_v intersect F) / max(degree_v,1) / .68 + bonus_v`

所有边属性非负，风险/跨区取值在[0,1]，固定使用原完整邻域的度。删除利用率、分母改为0.68是可解释的尺度约定，但不意味着新分数是概率。bonus保留为独立的敏感性因素。

这一写法沿用V4已经检查的逐边截断方式。用户草图中的能力项为：

`.09 * [1-min(sum_failed(edgecap)/(degree*55),1)]`

它随新增失效边能力增大而下降，并在没有失效邻居时仍产生.09/.68的基线分数（虽然最终被count门控屏蔽）。它不是“失效邻边的脆弱性累积”；不能仅凭分母固定就宣称总体单调。

合成反例，用于公式一般性质检查、不是本项目观测：degree=10，p=cross=0，每条失败边cost=.001；失效边能力集合从[0]变成[0,200]。草图总pressure约从0.163268降到0.146055；上述逐边修正版约从0.044150升到0.075065。当前正式边能力代理范围约24.50–81.92，该反例不代表当前数据必然出现同样下降，但说明草图没有无条件的单调保证。

正确规则在F⊆G时具有P_v(F)≤P_v(G)。若只开启风险传播、固定属性/完整度/阈值/bonus、失效过程不可逆且同步迭代，终态包含关系也可由逐轮归纳保证。全双机制系统不要求这种全局单调，因为重分配后的负载可以随受损集合非单调变化。

## 3. 软容量是调度情景，不等于安全能力，也不必为了触发过载强行设置

保留严格分配rho=1作为“有准入控制”的基线。另设rho=1.1作为应急尝试承接上限、gamma=1.0作为超过额定能力即停运的候选假设。这组值可以做仿真，但本项目尚无真实记录证明“超额10%可派入、超过额定立即停运”。超过设计吞吐也可能表现为排队、延误、拒收等，确定性立即失效必须明确标成模型假设。

相关理论可参考[Motter & Lai, 2002](https://journals.aps.org/pre/abstract/10.1103/PhysRevE.66.065102)：负载重分配可以造成过载级联；该文不能为本项目的rho=1.1或物流节点立即停运提供参数标定。

在所有本地/转移承接均满足`L_attempt <= rho*K_nominal`的定义下：

| rho | gamma | 过载触发是否可达 |
| --- | --- | --- |
| 1.10 | 1.00 | 可达 |
| 1.10 | 1.10 | 不可达，等于上限仍不满足严格大于 |
| 1.10 | 1.25 | 不可达 |

因此固定rho=1.1扫gamma=1/1.1/1.25时，后两项应标为“过载机制关闭”控制。若确实要比较三个活跃阈值，可另取rho=1.5统一测试gamma=1/1.1/1.25，或者联合扫描rho与gamma并标明gamma>=rho的不可触发单元；这些同样是压力测试范围，不是标定值。

另外，当前LP第一阶段尽量多承接、第二阶段仅最小化运输成本。直接放宽接收容量，可能为了走更便宜的路径而把货压到超过额定的设施，即便其他设施仍有可用额定能力。这会把调度政策的行为混入失效机制，必须显式报告。

建议新增一个清晰的调度对照：在最大承接量相同的可行解中，先最小化总额定超额`sum(max(L_attempt-K_nominal,0))`，再最小化运输成本。它可以避免只为省运输成本而制造不必要超额；仍不保证最大瞬时承接策略具有最优稳定服务。未来的安全承接策略应作为待检验的算法候选，而非先保证效果。

## 4. 实现范围不止newly_failed

至少涉及：

1. 分配器：永久保存K_nominal，另外计算dispatch_limit=rho*K_nominal；更新本地尝试承接、剩余接收空间、未分配需求和软上限约束。util分母必须仍是K_nominal，不能改成rho*K_nominal后把过载消掉。
2. 失效引擎：增加gamma/theta_risk和风险开关；删除pressure中的util；overload不受count门控；风险关闭时仍计算过载；统一risk的`>=`与overload的严格`>`及数值容差。
3. 状态缓存与配置：不同额定容量、rho、需求、承接规则使用独立分配缓存；不同风险参数使用独立闭包/轨迹缓存。不能在旧实例上修改参数却复用其闭包结果。
4. 服务与验证：区分尝试承接量、稳定服务量、未满足需求。旧代码把分配量记为已服务，不能直接把超额派入并将即将失效的设施上的量计成已完成服务。用于恢复AUC的时点应是每轮损伤/行动后的闭包稳定状态；中间派入量另列。gamma>1的可运行超额是否能实际完成服务，需要明确时间尺度与有效吞吐假设。
5. 日志：逐轮保存O-only、R-only、O-and-R三种互斥新失效集合，以及该轮util/pressure/阈值；外部初始损伤单列，不倒推归因。恢复后再次失败属于新事件，应区分事件数与唯一节点数。

当前V3分配器明确检查load<=K，并以K计算剩余能力。仅改newly_failed会让过载分支不可达；直接将K乘1.1又会混淆额定能力、派入上限与利用率基准。应建立独立V5模块及新结果目录，备份后实施。

## 5. 分位法可以做尺度对齐，不能称真实标定

已核对现有`54_svd_free_cascade.py`与正式`54c_threshold_calibration.csv`：旧0.45在原候选分布对应分位为约0.745547（74.55%），并非统一固定的80%或90%。该旧流程基于06b评分，权重和归一化口径也不同于当前V4，不能直接把旧阈值或旧候选分数平移。

可以在预先固定的参考8节点起点、完整属性/bonus和候选门控`count>0`下，计算新五项pressure，并取预先记录的分位作一个参考阈值。它属于分数尺度对齐，不是真实停运概率校准。阈值应在参考组确定后冻结，再用于未参与选择的随机起点和需求情景；不应每个测试场景、每个权重/bonus版本重新计算分位，否则会吸收待检验的敏感性。

风险判据统一采用`pressure >= theta_risk`，在报告中记录分位估计方法和相等值/并列值处理。新公式需保留宽区间扫描，可包含旧[0.42,0.44]作数字对照，但不能要求这个区间仍代表同一物理临界位置。

## 6. 验证和机制贡献如何报告

必做：

- 玩具图逐边新增失败邻居，压力不下降；没有失效邻居时风险传播不启动。
- 无失效邻居但超额时，过载可以独立触发；关闭风险传播后过载仍可触发。
- rho=1与gamma>=1是无分配型过载的解析控制；gamma>=rho单元标为不可达，而非“模型很稳健”。
- 只开风险时检验嵌套初始失效集合的终态包含关系，包括原7组异常组合；若违反，应检查实现/动态属性设定。
- 双机制出现非单调时，追踪第一次终态分岔之前的嵌套集合，核对共同存活节点的pressure、util和O/R标签。后续总差异不可凭直觉全部归为过载贡献。
- 独立重算额定能力、软分配上限、流量守恒、稳定服务与修复AUC；保留强贪心、固定预算和相同优化评价次数。

触发构成：报告“仅过载”“仅传播”“同时满足”三类，合计等于每轮新增内生失效。不能让两项单独占比相加超过100%后仍称独立贡献。触发标签不是因果贡献。

模拟机制效应：另在相同初始损伤与参数下运行四组机制消融（均关闭、仅过载、仅风险、双机制），对同一终态服务/累计服务指标报告差异及交互项。它有助于区分传播、过载和二者反馈，仍不能替代真实事件的因果验证。

bonus至少保留0/0.05/0.10的独立对照；阈值在对照之间冻结。保留原空间选点的同时增加空间bonus，需要分别解释持续外部暴露和选点集中损伤两个渠道，不能把加项当作已测量事实。

## 7. 建议拍板

采用独立V5候选：逐边非负五项pressure/0.68、不含util；独立额定超额判据；rho=1.1、gamma=1.0作为应急调度假设；严格rho=1作为必保留基线。风险阈值用固定参考分布作尺度对齐并进行宽区间扫描，bonus单列敏感性。保留当前V4以便解释改动来源。

本次完成的是设计审查和解析反例检查，未声称V5已实现、已通过实验或更符合真实物流运行。
