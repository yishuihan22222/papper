# V4失效机制修正与新旧对照

日期：2026-10-16。结论：已建立独立V4候选版本，去掉V3“已失效邻居均值”造成的风险稀释。原V3、正式输入、旧结果均保留，不能把本次修正解释为实证验证完成或投稿已达标。

## 改了什么，依据是什么

设F为失效集合，d_i为原完整网络的邻居数。采用固定分母：

`R_i(F,u) = [Σ(j∈N_i∩F) a_ij / max(d_i,1) + 0.07 min(u_i,1.6)] / 0.75 + b_i`

`a_ij = 0.21 + 0.16 p_ij + 0.12 cross_ij + 0.10 min(cost_ij/0.45,1) + 0.09[1-min(edge_capacity_ij/55,1)]`

其中u为严格容量分配后的利用率；b保留原空间/通道场景加项。失效仍要求至少一个失效邻居且R≥θ。风险是代理压力分数，不是概率。所有权重、原容量、名义需求、场景加项、修复成本和优化器不变；成本与容量的截断改为逐边变换后再累积，以保证每条边的贡献非负。因此这是有明确含义的机制改动，不能说新旧θ有完全相同的经验含义。

条件性质：若F⊆G且利用率相同，则每个共同存活节点的邻居压力不会下降，增量等于新增失效邻边的非负贡献之和除以固定d_i与0.75。它消除了均值稀释，但不保证整个LP耦合系统全局单调，因为利用率可随重分配改变。未对终态强行排序或做单调平滑。

固定邻居分数的阈值传播可参考[Watts (2002)](https://pmc.ncbi.nlm.nih.gov/articles/PMC122850/)，这里只借鉴数学结构，不借用其社会网络参数作为货运证据。真实负载重分配中，选择性移除也可能抑制级联，见[Motter (2004)](https://journals.aps.org/prl/abstract/10.1103/PhysRevLett.93.098701)；所以不能把“全系统必须单调”作为普遍物理定律。上述权重及场景加项仍待标定。

## 原问题是否消除

V3在θ=0.42第二次风险判断时，节点“新汉正西物流园E座”的风险从0.426178降至0.419448，两边利用率均为1。重建相同中间失效集合后，V4压力结果见56_counterexample_v4.csv；固定利用率的新增失效邻居不再造成分数下降。

原来两套起点的24个场景—阈值对照中，有7组终态数量倒挂。本次V4数量倒挂为0组，终态集合不满足包含关系为0组。这个观察只适用于本次固定输入，不等于证明任意场景均如此。

## 程序核验与恢复联通

共930项核验通过；包括独立标量公式、五节点全部16个邻居子集的81组包含关系、120组真实网络随机嵌套失效集合（固定利用率）、原反例重建、48次闭包/容量守恒、冷启动边与节点顺序重排、修复预算/AUC与失效状态持续性，以及125个备份原件哈希不变。核验计数含大量文件完整性检查，不是统计重复或现实验证样本。

在两套起点的4场景、风险结束/持续两种模式下，接入原强贪心做16组恢复联通检查，θ固定0.42、预算4、时段6。实际采取修复动作的条件为8组，完整序列、成本、服务AUC和轨迹见56e/56f。8节点扰动在当前严格分配代理下已能满足全部需求，贪心因此不花费修复资源；这也反映了原代理容量和两跳承接设定的冗余假设，需要边界敏感性检验。本次没有宣称局部搜索优于贪心，也没有完成全部算法的公平比较。

## 接下来应该做什么

1. 将V4作为机制修正候选，原V3作为诊断对照保留。不要将不同公式的旧阈值直接视为已标定参数。
2. 在合理业务假设下检查容量倍率、承接距离/两跳限制、城市映射以及权重/场景加项的不确定性；有停运样本才做外部阈值校准，没有则报告完整区间与结论边界。不得为制造级联、算法优势或漂亮图形而挑选参数。
3. 参数口径确定后，再把全部恢复算法放在相同数据、目标、预算、时域与评价次数下比较。现有48条阈值结果与16组恢复联通只支持机制检查，不能替代完整优化实验。
4. 当前是“容量约束分配与风险暴露传播耦合”模型，严格容量分配后u≤1，不能命名为物理超载级联。若论文要论证真实运力超载，需重新定义可观测超载/拒绝承接/服务损失的机制，而非仅修改名称。
