## 2. 关键缺口：第二个问句在当前设定下恒为零

这是本轮唯一需要你改设定的地方，所以推导写细一点。

**设定**（按你 §2）：余量按外生情景流失，`C(t) = C₀ − ρt`；任务可分批；转出不可撤回；转运无速率上限。

设批量 `x`，先在 t=0 转出 `y`，余下 `x−y` 在时刻 `t` 再转。

- 时刻 `t` 时可用的接收余量：`C₀ − y − ρt`
- 时刻 `t` 时仍需转出的量：`x − y`
- 可行性：`C₀ − y − ρt ≥ x − y` ⟺ **`C₀ − ρt ≥ x`**

**左边与 `y` 无关。** 也就是说：先转出的那部分虽然锁定了容量，但它同时也消耗了容量，一进一出抵消。

再看完成时间：整批完成时刻由最后一批决定，即 `t + τ + (x−y)/K`，**随 `y` 增大而变晚**。

**结论：在无速率上限的设定下，最优解恒为 `y = 0`（全部等）。** "至少应提前转出多少"的答案是**零**，这一问是空的。

> **这不是模型写错，是设定里缺一个让"早转"产生独立价值的机制。**

## 3. 补一条速率上限，第二个问句立刻有闭式解

**机制：转运与接收的处理速率有上限。** 这条有现实依据（车辆、班次、装卸能力有限），而且不需要概率、不需要博弈、不需要采购——完全符合你 §2 的约束。

设转运速率 `m`（单位时间可转出量），接收端处理率 `K`。转出与处理串行时，整条链的有效吞吐是两者的调和平均：

```
β = mK / (m + K)
```

（若可并行，β 取更大值；串行是最保守情形。）

**在 t=0 转出 `y`，余下 `x−y` 在时刻 `t` 起转，整批完成时刻约 `t + τ + (x−y)/β`。要求 ≤ h：**

```
y  ≥  x − β · (h − t − τ)
```

> **最低提前转出量**
> ```
> y*(t) = max{ 0 ,  x − β(h − t − τ) }
> ```

> **最迟等待时刻**（`y* = x` 处，即"再等就来不及转"）
> ```
> t* = h − τ − x/β
> ```

**再加上余量时钟**（`t ≤ (C₀ − x)/ρ`），取小者：

```
最迟等待时刻 = min{ h − τ − x/β ,  (C₀ − x)/ρ }
```

**两条公式正好对应你主线的两个问句，都是闭式，都不需要分布。**

### 3.1 反直觉结论：等待不是"少转"，而是"早转更多"

`∂y*/∂t = β > 0`。

**等得越久，现在必须先转出去的越多。** 因为等待吃掉了后面的转运窗口，剩下的量必须在更短的窗口里运完，所以只能提前挪走。

这条和直觉相反（直觉是"多等一会就少转一点"），而且**它是可检验的**：用一个固定缓冲规则做对照，固定缓冲规则的 `y` 不随 `t` 变，所以在 `t` 较大时会违反 `y*` 边界——**这就是你要找的"损失界"的来源。**

### 3.2 分批的最优解可以直接解出来（minimax）

若本地在 `r` 时刻恢复，整批完成时刻是两支的较大者：

```
T(y) = max{ τ + y/β ,  r + (x−y)/K }
```

令两支相等，得

```
y° = ( r − τ + x/K ) / ( 1/β + 1/K )
```

**这个 `y°` 是"两支同时完成"的平衡点**，也是 minimax 意义下的最优分批。用 `r_max` 代入即得鲁棒解（符合你 §3 的区间准则）。

**注意：`y°` 与 `y*(t)` 是两个不同的东西**——前者是"让两支同时完成"的平衡分批，后者是"再不转就来不及"的下限。论文里要分清，否则会被问住。

## 4. 修订后的主线（三句话）

1. **等待有价值（获得恢复信息），等待也有代价（吃掉转运窗口、流失接收余量）。**
2. **代价可以用两条时钟表达**：转运时钟 `h − τ − x/β` 与余量时钟 `(C₀−x)/ρ`，取先到者。
3. **最优策略不是"等或转"，而是一条边界** `y*(t)`：等多久，就必须先转多少。

**第 3 句是增量所在**——它把 1 维的"何时启动"变成 2 维的"何时、多少"，而这条边界的斜率 `β` 由转运与处理速率决定，可测、可核。
