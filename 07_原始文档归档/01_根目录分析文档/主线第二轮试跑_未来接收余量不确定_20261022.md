# 第二轮试跑：未来接收余量不确定，仍未突破主线退化

日期：2026-10-22。接续[第一轮报告](E:/sci23/主线第一轮试跑_20261022.md)及用户“继续”的要求。

**结论：放松“未来接收余量完全已知”后，分批与容量预告仍有业务价值，但当前单起点、单接收点模型的核心退化没有消失。继续扩大网络之前，需要重新确认论文真正要贡献什么。**

## 1. 这次具体改变了什么

接收点未来能力有两条可能的日历，调度者最初不知道是哪一条；每槽看到当前能力和源点是否恢复，再决定派出量。另设“可提前看到未来f槽能力”的信息情景，f=0、1、2、3。

所有恢复时刻与容量日历的组合均保留，保障要求覆盖全部组合；没有假定有利的恢复—容量相关性。接收能力在时间上的联合日历属于已知情景集，区别于仅知道每一槽独立上下界。前者需要相应业务依据，不能无证据删除不利路径。

核心仍是一个源点、一个接收点、无派出速率瓶颈、同质整数货物、共同截止期和恒定单位转运代价。没有加入博弈、采购或人为非线性。

## 2. 完整结果

网格：4槽；初槽接收能力为0，其余3槽能力各取0、1、2，形成27条日历，再取全部351种无序日历对；货量3/4、运输时滞1/2槽、恢复支持{1,2,3}或{1,2,3,4}，共2,808组配置。每组检查4种预告范围。

第二组恢复支持允许截至最后才恢复；第一组确保至少留一槽本地处理。加入第一组是为了检查结论是否仅由“可能完全来不及本地处理”造成。

| 指标 | 结果 |
|---|---:|
| 配置总数 | 2,808 |
| 可保障 / 不可保障 | 798 / 2,010 |
| 未知日历比预知日历增加等权总转运量 | 412组可行配置 |
| 最少必要派出规则与精确DP的等权目标不一致 | 0 / 798 |
| 逐槽最低能力模型保守判为无解、联合情景实际可行 | 282组 |
| 要达到预知日历的目标值，预告范围需大于运输时滞 | 116组 |
| 独立情景树MILP复核 | 82项通过，其中65项可行 |
| 相同已观察历史必须采用相同行动的检查 | 1,132项通过 |

82项复核包含原26项均匀抽样、12个分散的可行配置在4种预告范围下的48项，以及两个具体例子的8项；不是82个不同配置。MILP独立写流量约束与观察历史约束，不调用DP状态转移或分组函数。

网格数量是结构检查的覆盖范围，不能解释为现实频率。结果没有实际运营概率、恢复时长或处理能力的标定。

## 3. 两个可执行的认识

### 3.1 不要把“每一槽都可能低”拼成“所有槽同时最低”

取日历A=(0,2,1,0)、B=(0,0,1,2)，总接收能力都为3。若货量为3、运输需1槽，即使源点直到期限才恢复，也可在初始派出3，分别利用A或B的后续服务完成。

逐槽取两日历最低值却得到(0,0,1,0)，总能力只剩1，于是判无解。这个日历原本不在允许集合中。

它说明：若掌握跨时段的总量或排班约束，独立区间模型可能过度保守。若手里只有逐时下界、没有联合约束证据，就不能反过来保证“较好的联合日历一定成立”。这属于不确定集合表达的问题，不是新算法已经获胜。

### 3.2 预告一段运输时间以内的余量，可能仍然不够

取日历A=(0,2,1,0)、B=(0,2,1,2)，货量3，本地恢复后每槽处理1，运输需1槽，R∈{1,2,3,4}。归一化为τ/H=1/4、x/(KH)=3/4。两条日历仅最后一槽不同：

| 预告范围f | 相对期限f/H | 8个恢复×日历情景的最优总转运量 |
|---|---:|---:|
| 只知当前 | 0 | 22 |
| 提前1槽（等于运输时滞） | 1/4 | 22 |
| 提前2槽 | 1/2 | 21 |
| 提前3槽（本例预知整条日历） | 3/4 | 18 |

因为要判断是否值得利用早期能力，还需要知道较晚有没有替代机会。只知道货到了之后那一槽有多少能力，未必足以避免预防性分流。

这些是完美、准确预告的价值，不包括预测误差或获取信息的费用；“未来信息有用”本身也不是创新。近期半在线调度已有前瞻信息的竞争分析；2026年的批处理预印本亦讨论有限前瞻的局限与收益。[2023预印本](https://arxiv.org/abs/2306.06003)、[2026-10-12预印本](https://arxiv.org/abs/2610.16013)

## 4. 为什么仍然卡在创新

当前模型在初始没有外部队列时，令：

\[
q_{\mathrm{rob}}=[x-K(H-R_{\max})_+]_+,\qquad
A(C)=\sum_{s=L}^{H-1}c_s.
\]

由于恢复支持与容量日历是笛卡尔积，全部情景按期可行当且仅当：

\[
\min_{C\in\mathcal C}A(C)\ge q_{\mathrm{rob}}.
\]

必要性：最晚恢复与最少外部可用总量的组合也在允许集合中。充分性：最初派出q_rob，其他货留本地；外部可排队且无派出瓶颈，于是每条日历均可处理所派货量，本地最晚恢复也能处理剩余量。

这同时说明最优最坏总转运量仍为q_rob。逐步揭晓信息可以减少某些较好情景的转运量，但并没有使期限保障与最坏总量本身变成新的复杂问题。

第二轮的最少必要派出规则用精确未来可行性检查实现，**并未得到通用于未知日历的新闭式算法**。它在798组可行配置中匹配等权DP，仍只是有限网格证据，不是一般最优性证明。

因此目前不能把“分批动态算法”作为论文主创新。2023年的货运在线重规划与2025年的等待缓冲、货量拆分仍是必须正面回答的近邻，不能仅用2018年启动阈值作对照。

## 5. 当前判断及后续边界

已经得到可复现的基准模型、正反小例、解析退化条件和信息价值诊断；尚未得到足以认定为独立论文贡献的新机制。

如果继续保留这个方向，我建议把候选问题收窄到：**为减少不必要的预防性分流，接收点需要提前承诺哪些时段、多少可处理量；有限且可靠的容量信息能提供什么期限保障？**

这只是候选，不是给已有结果换标题就能成立。还需核查近期容量承诺/前瞻调度文献，明确“承诺”是可执行保障还是预测，并提供与之匹配的业务依据。没有这些依据，就保留本原型为诊断工具，暂不扩大到122点或硬写二区/三区创新。

本轮没有采集新运营数据；代码、精确对照及失败情景均已保存，旧实验保持不变。
