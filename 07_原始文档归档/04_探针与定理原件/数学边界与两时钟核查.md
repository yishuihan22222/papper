# 基础边界与“两时钟”新笔记核查

本轮并未采用工作区《主线修订评估_两个时钟与分批边界_20261022.md》的闭式解作为模型输入。以下区分能直接推导的基准事实与未证明的普遍结构。

## 1. 当前最小模型可直接推导的两个量

初始时刻0，截止期H，初始货量x，恢复后每槽能力K，最晚恢复时刻R_max；外部在槽s的剩余服务量为c_s。运输提前期L为整数槽，初始无外部队列或在途货，单一接收点，派出速率不绑定，费用只与总转运量成正比。

最坏恢复情景至少需要外部处理：

\[
q_{\mathrm{rob}}=[x-K(H-R_{\max})_+]_+.
\]

当前派出最早在槽L到达，下一槽再派出最早在L+1到达。若q_rob≤Σ_{s=L}^{H−1}c_s，当前整体可行，则维持保障所需的初始派出量下界为：

\[
y_0^{\min}=\left[q_{\mathrm{rob}}-\sum_{s=L+1}^{H-1}c_s\right]_+.
\]

必要性：若少于此量，最晚恢复情景中所需的外部工作量超过本轮已派量与下一轮起可利用能力之和。充分性：下界为正时，它不超过槽L的能力；用它填补将失去的服务机会，其余外部需求可在后续容量中安排，本地承担剩余量。若R_max情景不可行，不能套用该式声称获得保障。

这些是累计能力约束，不是已认定的新定理。本轮2,428组可行配置中，初始派出下界与等权精确DP所选最小首步均一致；minimax最坏转运量均等于q_rob。

## 2. 为什么纯minimax目标会退化

R_max情景要求至少q_rob转运，给出下界。在当前前提下，可以为R_max安排恰好q_rob的外部服务；更早恢复只会增加本地可服务量，适时停止后续转运即可维持可行性。因此可行情形的最优最坏总转运量恰好是q_rob。

这不意味着恢复信息无用。它能够减少较早恢复路径上的转运量，却不改变上述最坏值。若只报告最坏值，信息价值会被该目标隐藏。不能把等权情景均值的改善改写成鲁棒最坏值的改善。

## 3. 一般中间状态怎样不调用DP检查可行

对于候选派出动作，先更新本地、在途和接收端队列。以工作守恒方式处理已承诺的外部货物，计算从下一次新派货物能够到达之后，至截止期尚有多少未被占用的服务量。将它与最晚恢复下本地无法完成的剩余工作量比较，同时要求所有已承诺货物可在期限内完成。

单一接收点、共同截止期、无额外派出速率约束下，这个检查只需要累计剩余服务量；不需要未来恢复概率。每次选通过检查的最小派出量，就得到本轮的解析可行性规则。

该规则在8,234条测试路径中与等权DP的总转运量一致，均按期完成。这里的“一致”是与该DP选出的策略逐条比较，不是对所有规模、所有目标或每一情景分别最优的完整证明。

增加派出速率上限后的324组消融，102组可行，精确可行性驱动的最少派出规则仍全部匹配DP；该消融使用DP检查可行性，并未把上面的无速率上限解析规则错误用于有限速率情形。

## 4. “两个时钟”笔记中的具体问题

1. t+τ+(x−y)/K对y的导数为−1/K，随提前派出量增加而减小；原笔记写成“变晚”，符号错误。因此它的“最优y恒为0”证明不成立。
2. C₀−y−ρt≥x−y中的y抵消，只说明那一种固定总额度模型中的额度约束不变，不能推出期限目标也不变。累计额度和会过期的服务槽不是同一对象。本轮接收服务槽的例子在无派出速率上限时仍需提前派出1单位，构成对“恒为0”的反例。
3. mK/(m+K)对应整批先完成运输、再完整处理且不能重叠的假设。一般运输—处理流水可重叠，不能统一用调和平均替代事件账本；例如m=K=2时，充分流水后的稳态瓶颈率是2，而调和式是1。
4. 对y_min(t)=[x−β(H−t−τ)]_+，t=H−τ−x/β对应y_min=0，并非y_min=x；后者对应t=H−τ。原笔记把两个端点写反。
5. 两支完工时间相等给出的y°还要截断到可行区间，并满足接收额度/时序。它对应最小化最大完工时间；本轮是硬期限下减少转运量，目标不能互换。
6. “不加博弈上限就是三区”“博弈是唯一二区入口”没有依据。本轮不继承该判断。

逐个数值反例及复核结果见structural_checks.json。原笔记保留，不在本轮覆盖。
