## 1 一句话研究问题

> **恢复时间不确定、接收余量会随等待减少时，最迟还能等多久、至少应提前转出多少，才能保住完成期限，并减少不必要的转运？**

工作题目：**《接收余量流失下的限时等待与分批分流决策》**

## 2 为什么这条路对：它修的是 V7 的结构性死因

V7 的死因不是数据少，是**结论全部落在自选参数上**：γ=1 是自选的、ρ=1.1 是自选的、K=1.25L 是构造的。所以「20 个百分点」无法外推，也无法辩护。

| 量 | V7 | 方向 C | 性质 |
|---|---|---|---|
| 转运时滞 τ | 无 | **道路查询 `Duration_mins`，1624/7381 对** | 可观测（但非实测） |
| 截止期 D | 无 | 服务承诺，**由决策者设定** | 可控（政策变量） |
| 处理时间 x/K | K 是代理 | **只需比值 x/K，不需绝对 K** | 无量纲 |
| 恢复时间 r | γ 是自选常数 | **不确定，且这就是研究对象** | 被研究 |
| 退出阈值 γ | 自选、不可观测、不可控 | **不存在** | 已消除 |

两条关键变化：

1. **最难的参数从「必须知道」变成「不需要知道」。** 不需要绝对 K，也不需要绝对 L，只需要处理时间 `x/K` 这个比值 → **V7 的标定死结自动消失**。
2. **不确定性从「隐藏缺陷」变成「研究对象」。** 同一个「参数不确定」，位置一换，性质就反了。

连续性：V7 的核心机制是「派入规则自己把节点推过阈值」。在时间域里它变成「按最短提前期分流 → 最快的点被填满 → 它不再最快」——同一自致失效机制，但参数量是实测的、阈值是闭式的。

## 3 首版模型（少一个机制，更容易看清贡献）

先做**一个受损点、一个接收点、一批任务、少量决策时刻**，再扩到两个接收点。

必须明确的假设（写在第一页）：

| 项 | 首版设定 |
|---|---|
| 时间 | 当前 t、截止 D、剩余期限 `h = D − t`、未完成量 x |
| 恢复 | 物理恢复时刻 R；残余 `r = R − t` 的**区间** `[r_min, r_max]`，不用分布 |
| 观察 | **二元**：只知「已恢复/未恢复」 |
| 本地 | 恢复后有效处理率 K；首版无新到达；已有任务占用须从有效能力扣除 |
| 接收余量 | `A`：接收点在到货、排队、已有承诺和截止期共同约束下能为本任务完成的余量，**不是瞬时空闲机器数** |
| 余量变化 | 首版**外生、可观察状态 + 明确未来情景集合**；未来路径不能偷渡给在线策略 |
| 任务 | 可分批；分流**不可撤回**；运输有时滞 τ |
| 保障 | 区间情景下的**期限保障**，报告对应转运代价 |

**暂不加入**：对称均衡、估计器学习、增容采购、全网传播。

## 4 两个边界（只判断本地可行性，不是最优性）

在「恢复后以固定速率 K 独占处理剩余量 x、无额外到达」的特例中：

```
r_max + x/K ≤ h      ⟹ 本地等待在整个区间内均可按期完成
r_min + x/K >  h     ⟹ 本地等待在整个区间内均不能按期完成
其余                  ⟹ 本地按期可行性未定
```

**关键纠正**（此前版本的错误）：这两条是**可行性**边界，不是最优性边界。

| | 外部可接住 | 外部接不住 |
|---|---|---|
| **本地可按期** | **真正的决策区**（等待可行但未必最优） | 等待是唯一可行 |
| **本地不可按期** | 必须外转，且外转可行 | 无解（只能改期限或改结构） |

**只有左上格是决策问题。** 中间区用**区间鲁棒准则**，不必假设分布。

另：固定 `x/K`、以 h 为横轴时，两边界距离 = `r_max − r_min`。这个局部宽度**不是**整个序列决策问题中所有不确定性的度量；不能靠缩窄区间制造确定结论。

## 5 第二个边界：最低外部处理需求

记 `[z]_+ = max(z,0)`：

```
S_min = K(h − r_max)_+
q_min = [x − S_min]_+
```

`q_min` 是**为保障所有允许恢复情景而最终需要的外部处理量下界**，不是当前必须立即转出的量，也不保证外部真有足够能力。

真正的问题是：在「尚未恢复、最晚恢复情景仍可能」的路径上，等待到下一决策时刻后，更新的外部可保障量是否仍覆盖更新后的 `q_min`？若眼下可保障、等待后不再可保障，就找到了**等待损失可行性的条件**。

## 6 两时钟与最低提前转出量（本方向的核心机制）

### 6.1 陷阱：无速率上限时「至少提前转出多少」恒为零

设定：余量外生流失 `C(t) = C₀ − ρt`，可分批，转出不可撤回，**转运无速率上限**。

设批量 x，t=0 转出 y，余下 x−y 在时刻 t 再转：

- 时刻 t 可用余量 `C₀ − y − ρt`；仍需转出 `x − y`
- 可行性：`C₀ − y − ρt ≥ x − y` ⟺ **`C₀ − ρt ≥ x`**（左边与 y 无关）
- 完成时刻 `t + τ + (x−y)/K`，**随 y 增大而变晚**

⇒ **最优解恒为 y = 0**（全部等）。第二个问句是空的。

> 这不是模型写错，是设定里缺一个让「早转」产生独立价值的机制。

### 6.2 补一条速率上限，闭式立刻出现

设转运速率 m、接收端处理率 K，串行时有效吞吐是调和平均（最保守）：

```
β = mK / (m + K)
```

在 t=0 转出 y、余下 x−y 在时刻 t 起转，整批完成时刻约 `t + τ + (x−y)/β`。要求 ≤ h：

```
y*(t) = max{ 0 ,  x − β(h − t − τ) }        最低提前转出量
t*    = min{ h − τ − x/β ,  (C₀ − x)/ρ }    最迟等待时刻（两条时钟取先到者）
```

**两条公式正好对应主线的两个问句，都是闭式，都不需要分布。**

### 6.3 反直觉结论（主结果候选）

```
∂y*/∂t = β > 0
```

> **等得越久，现在必须先转出去的越多。** 因为等待吃掉了后面的转运窗口，剩下的量必须在更短的窗口里运完，所以只能提前挪走。

这与直觉相反（直觉是「多等一会就少转一点」），而且**可检验**：固定缓冲规则的 y 不随 t 变，所以在 t 较大时会违反 `y*` 边界 → 这就是「损失界」的来源。

### 6.4 分批 minimax 平衡点

若本地在 r 时刻恢复，整批完成时刻是两支的较大者：

```
T(y) = max{ τ + y/β ,  r + (x−y)/K }
```

令两支相等：

```
y° = ( r − τ + x/K ) / ( 1/β + 1/K )
```

用 `r_max` 代入即得**鲁棒解**。

> **`y°` 与 `y*(t)` 是两个不同量**：前者是「让两支同时完成」的平衡分批，后者是「再不转就来不及」的下限。论文必须分清，否则会被问住。

## 8 前瞻信息边界（本方向唯一已成立的定理）

见 `05_方向E_容量信息前瞻边界.md`。核心：

```
对任意 H≥3、1≤L≤H−2：  J_f = 4x (f≤H−2)  ;  J_f = 3x (f=H−1)  ⇒  f* = H−1
```

**运输时滞不能单独确定充分的容量预告范围。** 固定 L=1 增加 H，`f*/L` 任意增大。

## 9 创新定位的诚实评估

### 9.1 四个零件各属已有传统

| 零件 | 归属 |
|---|---|
| `max(τ, r, a)` 瓶颈归并 | CPM/PERT 最近开始时间 |
| `t* = D − a − x/(K+B/c)` | 项目赶工（time-cost tradeoff）的重排 |
| 阶跃损失 + 临界分位缓冲 | 安全提前期 / 报童 |
| 投运输 vs 投能力 | 边际分析 |

### 9.2 已作废的说法（不可再用）

| 说法 | 处置 |
|---|---|
| 偏差 `= (1+κ)y/K` | **删**。κ 无依据，符号靠不住 |
| 命题「缓冲必然失效」 | **删**。依赖符号 |
| 排序反转条件 | **降为支线**（可作「若估计反馈存在」的讨论） |
| 二元观察是「最弱信息结构」 | **改**。它是有限信息设定，不是最弱；最优收益不降低 |
| 「多数提前分流多余」 | **不能写**，除非量化为网格占比 |
| 增容按离散档位 | **删**（首版不做采购） |

### 9.3 当前可守的贡献定位

> **面向限期完成的容量窗口感知分批分流规则及其信息需求。**

- **已站住**：一个具体模型中的反例边界（`f*=H−1`）、可复现的分批规则与精确对照（283 项核验）、信息不足造成额外分流的结构证据（412 组 / 116 组）
- **尚未站住**：相对最接近可迁移规则的独立增量、实际日历下信息需求的简便诊断

### 9.4 唯一可能真新的落点

**分流使 r 的估计误差变成内生且单边** —— 所有人按 `r̂` 选最小 → 同点被挤 → `x/K` 上升 → 实际 lead 高于 `r̂` → 偏差随分流规模增长。

但 `主线修订评估` 已**否决**这条：`r_eff = r̂(1+κσ)` 需要 κ>0，而 κ 没有任何依据。**「分流增加排队」不等于「设施恢复变慢」。**

**替代结论（不依赖符号）**：最迟等待时刻 + 最低提前转出量 + 规则损失界。

## 10 自检标准

> **能否说出一句审稿人读前写不出来的话。**

- 「钱买不到提前期」能写出来（`t* = D − a − x/(K+B/c)`，B→∞ 时 `t* → D−a`）
- 「运输时滞不能单独限定必要的信息前瞻范围」能写出来（`f* = H−1`）
- 「分流把恢复时间估计系统性推向悲观、偏差随分流规模增长」**写不出来**（κ 无依据）

## 12 停止线

| 触发现象 | 处置 |
|---|---|
| 加入余量流失后仍只剩已知阈值或标准流 | 重新评估贡献，**不靠增加模型复杂度补救** |
| 闭式与精确求解不一致 | 用最小反例检查假设、公式和实现，**三者均允许修正** |
| 区间太宽、保障过于保守 | 如实报告；只有新证据才可缩窄 |
| 改善仅在挑选参数或较弱基线下出现 | 降低主张或停止该分支，**不硬凑投稿档次** |
| 优势只在极少情景出现 | 不把网格占比解释成现实概率 |

## 13 最小验证路线（3—5 个研究工作日的可行性核查）

| 步骤 | 必须产出 | 继续条件 |
|---|---|---|
| 定义与近邻核查 | 状态、观察、动作、保障目标、基准及最直接文献差异 | 能说清新增机制，不把已有阈值重命名 |
| 精确小例 | 两三个决策时刻的穷举/DP；确定性特例与时间展开流核对 | 同一信息和业务约束下账本一致 |
| 机制消融 | 固定余量 / 余量流失；去掉恢复信息；改变运输时滞 | 能定位行动变化与损失来自哪里 |
| 稳健性与资源账 | 同保障下费用、转运量、超期量、可保障范围、求解代价 | 结果不依赖单个有利参数或弱基线 |

**必须比较的基线**：立即全部分流、固定恢复缓冲规则、考虑余量的分批规则、小例的同信息精确策略。

**若某规则在同一保障目标下无可行解，应报告其可行性失败，不能让它放松保障后只比成本。**
